# Invocation: Setup (first grimoire, join one, or adopt a folder)

## Purpose

Hold the onboarding conversation. A person who has just installed Arcana, or
who has been told "we keep that in the Kutta grimoire", should be able to say
"set me up" and end with a grimoire on disk, registered, and usable, without
learning git or Arcana. A person with a folder of notes should be able to make
it a grimoire in one exchange. Engineers get the same flow with fewer
questions.

Rites behind the paths: `rites/install_grimoire.py` (join by link),
`rites/adopt_grimoire.py` plus `rites/sync_library.py` (adopt a folder),
`rites/summon.py --check` (state). Everything else here is conversation.

## Invocation

```
/grm-setup
/grm-setup <git url>
/grm-setup <folder>
```

## Preconditions

None. This command works from any directory and is the one `/grm-*` command
that does not need an active grimoire. Never ask for a token, password, or
personal access token: git already holds the user's credentials for their host,
and when it does not, git's own credential helper prompts once (a browser
window on Windows and macOS, a terminal prompt on Linux). Say that this prompt
may appear and move on.

## Workflow

### 1. Look before asking

```bash
~/grimoires/arcana/bin/arcana summon --check --format json
```

Read the envelope. It tells you whether the library exists, which grimoires are
registered, whether skills and the routing block are current, and whether
anything drifted. Do not ask the user for facts this envelope already holds.

### 2. Branch on what you found

- **`$target` is a repository link** (`https://`, `git@`, or a path that is a
  git repository). Go to step 3.
- **`$target` is a folder on disk that is not a git repository** (or a
  directory under `~/grimoires/` without `grimoire.json`). Go to step 4.
- **No grimoires registered.** Ask one question, offering three answers:
  1. *Join a grimoire your team already has*: "paste the repository link your
     teammate or your wiki gave you".
  2. *Start a new grimoire from scratch*: hand off to `/grm-create`.
  3. *Turn a folder of notes you already have into a grimoire*: ask for the
     folder and go to step 4.
- **Grimoires already registered and nothing drifted.** Say so in one line,
  list them with their descriptions, and offer the same three answers plus
  "nothing, I'm set". If the check reported drift (stale skills or routing
  block, a grimoire behind its remote), offer `/grm-update` first.

### 3. Join: run the rite

```bash
~/grimoires/arcana/bin/arcana install_grimoire "<url>" --format json
```

Accepts `https://...`, `git@host:path.git`, and local paths. The rite derives
the directory name from the repository name (`--name` overrides it), clones or
fast-forwards into `~/grimoires/<name>`, checks for `grimoire.json`, records
the library entry, and registers skills.

Read the envelope and report from it, never from assumption:

- `status: ok`: say where it landed and what it is (from the grimoire's
  `grimoire.json` description). Continue to step 5.
- `status: blocked` with `manifest: missing`: the repository is on disk but is
  not a grimoire yet. Offer to adopt it (step 4 on `~/grimoires/<name>`) and
  explain that adoption only writes a small identity file.
- `status: error` on clone: the three causes, in order of likelihood: the URL
  is wrong (compare it with what the teammate sent), the host needs VPN, or git
  has no credential for the host yet (re-run and watch for git's prompt). Do
  not retry in a loop; ask the user which it is.

### 4. Adopt: make a folder a grimoire

The folder must live under `~/grimoires/`; if it is elsewhere, ask before
moving it there (the layout is what the other rites resolve through). Then
gather, one question at a time:

- A **skill prefix**: a short lowercase slug (two to four letters) matching
  `^[a-z][a-z0-9]*$`, unique across installed grimoires (`notes-grimoire` ->
  `nt`). Suggest one from the folder name.
- A **one-line description** (default `"<name> grimoire"`).
- The **naming convention** the folder follows: offer `snake_case` as the
  default or `preserve` when the material keeps its own casing.

```bash
~/grimoires/arcana/bin/arcana adopt_grimoire <directory> --skill-prefix <prefix> --description "<desc>" --naming <convention>
~/grimoires/arcana/bin/arcana sync_library --apply
~/grimoires/arcana/bin/arcana sync_skills
```

The adopt rite refuses to overwrite an existing `grimoire.json` and refuses a
prefix collision; report its envelope. Adoption writes only the manifest; the
folder's content is untouched. Suggest `/grm-check` afterwards so the user
sees what the validators think of the existing material, and `/grm-add` for
anything still sitting loose.

### 5. Close the loop

1. Tell the user to open a fresh agent session so it sees the grimoire's
   skills (agents cache skill listings).
2. Name the verbs they will use day to day, in plain words: ask (just talk;
   the agent routes through the grimoire), `/grm-add` to write something down
   or file a document, `/grm-save` to share what they changed, `/grm-update`
   to pick up everyone else's changes, `/grm-check` when they want to know the
   grimoire is in good shape.
3. If the user is an engineer who mentioned a group or org URL, point out the
   terminal path for discovering many grimoires at once:
   `bash ~/grimoires/arcana/rites/summon.sh --scope <org url>`.

## Rules

- One question at a time, plain words, no git vocabulary unless the user used
  it first.
- Never ask for credentials. Never store a token in a file.
- Never clone into any directory other than `~/grimoires/<name>`; the rites
  own the layout.
- Quote the rite envelopes for every claim about what happened.
